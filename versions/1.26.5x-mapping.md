# Minecraft 1.26.50 stable native mapping

Protocol 2169 uses the outgoing Dragonfly snapshot at fork commit `dc54cf36`. Exact block, item, creative,
crafting, potion, and item-tag blobs are stored under `data/v2169`; their Git blob IDs, decoded counts, and
SHA256 values are locked in its manifest.

Against stable Dragonfly `4c7b5074`, the vanilla mapping contains:

- 22,091 native block states and 17,499 protocol-2169 target states;
- 2,076 native items and 1,976 protocol-2169 target items;
- 1,417 native-only block-state fallbacks to target air;
- 100 native-only items hidden clientbound and rejected serverbound.

Minecraft 1.26.50 moved stair corners and pane/bar/fence connections into explicit server block state. Older
registries omit those properties. The shared mapper therefore:

1. adds neutral `minecraft:corner=none` or four false connection properties when resolving an old target
   state to native;
2. strips those properties when resolving any native visual variant to the old target state;
3. applies the same compatibility step after historical block-name upgrading;
4. only then classifies a state as an air fallback.

This rule is central because every historical adapter crosses the same native schema change. Focused tests
prove straight/corner stairs and disconnected/connected panes collapse to the correct target state rather
than air.

Protocol 2169 is included by registry-aware catalogues. Protocol 2168 shares its
unchanged historical registries and reuses only the 2169 wire codecs; both map
directly to native. Custom item entries are allocated separately, validated on
subsequent registries, and retain native creative selection IDs.

The parameterless catalogue is empty because every historical adapter now needs
native mappings. Real-client checks must be repeated against this native baseline.
